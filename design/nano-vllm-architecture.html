引擎

它把 Python 的一次调用，拆成许多轮小任务。

先看 generate() 怎样循环调用 step()。一条 Sequence 持有输入、已生成 token 和缓存进度。每轮只有模型与采样产生候选，是否追加、是否结束由调度器处理。

02

调度器

GPU 一次能处理多个请求。调度器决定下一批由谁组成。

直接从两个队列入手。waiting 里的请求需要先把输入算进缓存。running 里的请求可以继续生成。只要本轮排进了 prefill，就走 prefill；这一轮没有可排入的输入时，才尝试 decode。

schedule / preempt

03

KV 缓存管理

KV 是模型留给后续 token 读取的历史。把它切成等大的块，就能按需分给各个请求。

CPU 上的 BlockManager 管块号和引用数，实际张量放在 GPU 的块池里。示例中 A 和 B 的开头相同，块表可以指向同一个物理块。真实代码按连续的完整前缀匹配，遇到不相同的块就停止。

BlockManagerGPU 块池
04

执行器

它把 Python 里的序列状态，翻译成模型能直接使用的输入和地址。

从 prepare_prefill() 和 prepare_decode() 对照着读。前者可能一次送入多个位置，后者每条序列只送一个位置。两条路径都会告诉模型这一轮的新 KV 写到哪里。

两个 prepare 方法
05

模型与采样

模型把上下文转成词表分数，采样器从中选出下一枚 token。

源码把模型本身和执行细节分开。Qwen3 定义层结构，Triton 将新 KV 写入指定槽位，FlashAttention 读取这一轮允许看到的历史。引擎拿到采样结果，又能安排下一轮。
