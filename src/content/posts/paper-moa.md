# 前言

上一篇 [MiTA](../paper-mita/) 把注意力看作一次信息检索：先由少量地标准备候选，再让许多 query 共享搜索结果。如果不想在推理时搜索候选，还有另一条路：提前规定每个注意力头能读多远，只在这个范围内计算。

最直接的做法是滑动窗口，但所有头都用同样大的窗口，往往不是好选择。有的头只需要附近几句话，有的头却需要回头找很早以前的事实。把窗口平均分给它们，既可能浪费，也可能不够用。

[Mixture of Attention Spans](https://arxiv.org/abs/2406.14909v3)，简称 **MoA**，研究的就是这份预算该怎样分配。它不改变模型权重，而是离线为不同层、不同头搜索窗口规则，推理时直接套用。理解它的关键不在于记住一个窗口公式，而在于看清楚：**怎样判断哪里可以少读，以及怎样把省下来的空间留给真正需要远处信息的头。**

接下来用一份长会议记录贯穿全文。记录前面提到“项目代号是青鸟”，结尾要求模型回答项目代号。答案很短，需要读取的信息却可能隔着几千个 token。

# 滑动窗口

## 读取范围

完整的因果注意力允许当前位置读取自己及之前的全部 KV。记录越来越长，每生成一个 token，就要与更多历史 key 比较，再按注意力权重汇总 value。历史 KV 还要留在显存里，供后续位置继续读取。

滑动窗口把读取范围限制在最近一段。例如，窗口只覆盖最后 2048 个 token，那么超出范围的历史 KV 就不再直接参与这个头的计算。省掉的是匹配、加权汇总，以及解码时存储和读取这些 KV 的开销。

MoA 沿用这个规则，同时保留开头少量 token，论文默认保留 64 个。这部分对应常见的 attention sink 处理，并不是把长记录压缩成摘要，也不是额外保存所有关键事实。记录中间的“青鸟”仍然可能落在窗口之外。

下图把完整注意力与短窗口的可读位置画在同一条时间线上。未来位置始终不能读取，窗口只是进一步缩小了历史范围。

![完整因果注意力读取全部历史，滑动窗口只保留开头 token 和最近一段，远处事实可能被排除](/img/posts/paper-moa/window-mask.svg)

窗口内仍然是普通注意力：计算 query 与 key 的分数，经过 softmax，再加权读取 value。**窗口决定哪些位置有资格参与，注意力权重决定这些位置各占多少。** 换一份文本，权重会变，但同样长度下的窗口边界不会因为内容而移动。

## 远处的信息

> **模型有很多层，不能把前面的信息一层层传过来吗？**

可以。即使单层只读局部，较晚位置的表示也可能已经融合了更早的信息。但“存在一条间接传播路径”不等于“原来的事实一定能被准确保留”。一句项目代号经过许多次混合之后，未必还能像直接读取原始位置那样可靠地找回来。

MoA 的出发点不是证明局部注意力无法利用长上下文，而是观察到：对已经训练好的 LLM，直接把所有头切成统一短窗，会明显伤害长距离检索。与其要求每个头都靠间接传播弥补，不如让一部分头继续看得足够远。

# 注意力头的分工

多头注意力不是把同一份工作机械地复制很多遍。不同头有不同的 Q、K、V 投影，形成的注意力模式也不同。论文在预训练模型中观察到，有些头主要看局部，有些头则在很大的历史范围内读取信息，而且这些差异跨数据样本仍有一定稳定性。

因此，同样削掉 2048 个位置，对不同头的影响可能完全不同。一个原本就几乎不利用远处信息的头，缩短后变化不大；一个负责读取早期事实的头，可能因此失去关键输入。MoA 搜索的是这种差别，不需要先人工给每个头贴上“语法头”或“检索头”的标签。

用一个教学配置看预算怎样流动。假设输入长 8192 个 token，只有四个头，窗口跨度已经包含保留的开头部分：

| 分配方式 | 头 1 | 头 2 | 头 3 | 头 4 | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 统一窗口 | 4096 | 4096 | 4096 | 4096 | 16384 |
| 不同窗口 | 2048 | 2048 | 4096 | 8192 | 16384 |

两种方案的平均跨度都是 4096，保留的 KV 数量相同。第二种方案却让一个头保留了完整历史，代价是让另外两个头看得更短。下面将同一份预算画成四条读取范围。

![相同的总 KV 预算，统一分配与异构分配给不同注意力头提供不同的读取范围](/img/posts/paper-moa/head-budget.svg)

如果头 4 对远处的项目代号很敏感，而头 1、头 2 缩短窗口的损失较小，这次交换就值得。反过来，若头 1 恰好承担重要的远距离读取，盲目缩短它照样会出错。所以，**异构本身不是答案，知道怎样分配才是。**

这也解释了名字里的 mixture：MoA 混合的是不同注意力头的跨度，不是像 MoE 那样为每个 token 选几个 FFN 专家，也不是像 MiTA 那样让 query 路由到一组动态候选。各个头仍然计算，只是读取范围不同。

# 弹性窗口

只为 8192 长度配好窗口，还不够。请求可能只有 2048 个 token，也可能长到 32768。若一直保留固定数量，输入越长，能直接覆盖的比例就越小；若所有窗口都按相同比例放大，主要看局部的头又会占用不必要的空间。

MoA 为每个头配置一条随输入长度变化的线性规则。记请求的输入长度为 $N$，用 $h$ 索引所有层中的注意力头，头 $h$ 的跨度为 $S_h$，基础跨度为 $\alpha_h$，增长系数为 $\beta_h$：

$$
S_h(N)=\alpha_h+\beta_h N.
$$

跨度包含开头保留区与最近的滑动窗口。超过实际历史长度时，只能读取已有位置；实现还要按计算块对长度取整。下面先忽略这些边界细节，看三种教学规则：

| 规则 | 2048 长度 | 8192 长度 | 直观含义 |
| --- | ---: | ---: | --- |
| $\alpha_h=1024,\ \beta_h=0$ | 1024 | 1024 | 一直保留固定跨度 |
| $\alpha_h=0,\ \beta_h=0.5$ | 1024 | 4096 | 保留约一半跨度 |
| $\alpha_h=0,\ \beta_h=1$ | 2048 | 8192 | 覆盖完整历史 |

第一种适合需求主要由局部范围决定的头，第三种为全局读取保留空间。论文也允许基础跨度与增长项同时存在。下图中，三条线在短输入时可能靠得很近，输入变长以后却对应完全不同的缓存需求。

![固定跨度、按比例增长与完整历史三种窗口规则随输入长度变化](/img/posts/paper-moa/elastic-spans.svg)

这里的“弹性”是**不同长度的请求套用同一条规则**，不是每个 query 现场判断该看多远，也不意味着生成时每一步都要扩容缓存。窗口内容会随着位置滑动，窗口容量怎样设置，则属于一次请求的执行计划。

# 窗口的离线搜索

公式只提供了候选。一个有 32 层、每层 32 个头的模型，共有 1024 个头，即使每个头只有几十条规则，全部组合也不可能逐一跑完整评测。

MoA 把这个问题拆成两步：先估计每个候选会造成多少损失，再在预算内组合它们。得到的配置可以在后续许多请求中重复使用，而不是为每份会议记录重新搜索。

## 校准数据

先要有一批能暴露长距离依赖的数据。如果用普通文章，对全文每个位置都计算下一个 token 的预测损失，大量位置只凭附近内容就能预测得不错。这样的平均损失可能掩盖一个问题：模型在结尾已经读不到开头的关键事实。

论文使用 MultiNews 的长文摘要任务，把损失集中在回答部分。要生成摘要，模型需要利用分散在上下文中的内容，远处连接的重要性更容易反映出来。

监督文本也有讲究。假设人类摘要写“青鸟项目延期”，原模型却更习惯先写“会议决定”。如果强行按人类摘要计算梯度，得到的信号不仅包含长距离读取需求，还包含改变原模型措辞的需求。

MoA 的目标是尽量保留原模型能力，因此先让原始完整注意力模型生成摘要，再把这些摘要作为监督。它更关心“屏蔽连接后，原模型本来会给出的回答变得多难预测”，而不是趁机纠正模型的全部错误。

**免训练不等于不做反向传播。** 校准会计算梯度，但不更新模型权重；梯度在这里是一把测量工具，用来估计窗口缩短的影响。

## 连接的影响

最简单的想法是看注意力权重：一条连接的权重很小，删掉应该没什么影响。但权重只表示读了多少，没有说明这部分信息对最终回答有多重要。一个占比不大的 value，也可能提供无法替代的项目代号。

记校准回答的交叉熵损失为 $L$，头 $h$ 中 query 位置 $i$ 读取 key 位置 $j$ 的注意力权重为 $A_{h,i,j}$。MoA 同时计算这个权重和损失对它的梯度：前者描述当前读取量，后者描述改变读取量会怎样影响回答。

还有一个容易漏掉的细节：**屏蔽一条连接，不只是把它的权重清零。** softmax 的总和必须仍为 1，其余连接的权重会一起上升。

把某一行缩成三个位置，原权重为 $[0.5,0.3,0.2]$。屏蔽第三个位置后，前两个权重需要除以剩余总量 0.8，变成 $[0.625,0.375,0]$，而不是 $[0.5,0.3,0]$。下图展开了这次重新分配。

![屏蔽一个注意力位置后，剩余权重重新归一化；损失估计同时计入删除和重分配的影响](/img/posts/paper-moa/attention-influence.svg)

暂时省略头和行的下标，用 $a_n$ 表示这一行第 $n$ 项的原权重，$g_n=\partial L/\partial a_n$ 表示相应梯度。屏蔽第 $j$ 项后，权重变化为 $\Delta a_n$。在 $a_j<1$ 时：

$$
\Delta a_j=-a_j,\qquad
\Delta a_n=\frac{a_n a_j}{1-a_j},\quad n\ne j.
$$

第一项是直接删除，第二项是其余位置补上被释放的权重。将它们代入一阶泰勒近似，就得到屏蔽这条连接造成的损失变化估计 $E_j$：

$$
E_j=\sum_n g_n\Delta a_n
=-g_j a_j+
\sum_{n\ne j}g_n\frac{a_n a_j}{1-a_j}.
$$

这就是论文的 attention influence。估计值为正，表示屏蔽倾向于增大损失；它也可能为负，所以并不是一个保证非负的“重要性分数”。关键是同时考虑所有受影响的读取量，而不是只把原权重与梯度相乘。

## 预算分配

对不同样本取平均后，每个头、每个输入长度都有一张影响矩阵。某条窗口规则会屏蔽一片历史位置，把这些位置的平均影响加起来，就能估计该候选带来的损失。

用 $r$ 表示候选规则，$M^{(r)}_{h,i,j}=1$ 表示该连接被屏蔽，$\bar E_{h,i,j}$ 表示跨样本平均的连接影响。头 $h$ 采用规则 $r$ 的损失估计记为 $D_{h,r}$：

$$
D_{h,r}=\sum_{i,j}M^{(r)}_{h,i,j}\bar E_{h,i,j}.
$$

这里又做了一层近似：把单条连接的影响相加，代替多条连接同时删除后的真实变化。不同头之间的相互补偿、高阶变化，也没有完整进入这张表。它的价值是把昂贵的模型评测，转成求解器可以反复查询的数字。

接下来，每个头的每条候选都有两项信息：预计占用多少 KV，以及预计增加多少损失。把问题缩成两个头，假设影响估计给出了下面这张教学表，损失数值不是准确率，也不是论文实测：

| 注意力头 | 跨度 2048 的损失估计 | 跨度 4096 的损失估计 |
| --- | ---: | ---: |
| 头 A | 0.20 | 0 |
| 头 B | 0.01 | 0 |

若总预算只有 6144，就无法同时给两个头长窗。把 4096 留给头 A、2048 留给头 B，预计总损失为 0.01；反过来则是 0.20。这就是搜索要完成的交换：不是选权重最大的头，而是把空间留给缩短后损失更大的头。

论文将预算写成平均密度。记总头数为 $H$，密度为 $\rho$。先按各头独立保存 KV 的情况计数，将截断后的实际跨度相加，再与完整注意力的 $HN$ 个位置比较：

$$
\rho(N)=\frac{\sum_{h=1}^{H}S_h(N)}{HN}.
$$

前面四个头的例子里，两种方案都是 $\rho=0.5$。这是平均预算，不要求每个头都只保留一半，也不等于整张因果注意力矩阵恰好剩一半元素，更不等于整个模型显存减半。

MoA 用混合整数规划，把这个选择扩展到所有头和候选规则。搜索还同时考虑多个输入长度：某个方案可能在短文本上更好，在长文本上更差。论文先保留不能被其他方案在各个长度上同时胜过的 Pareto 候选，再在未参与影响测量的长度上跑模型、测真实损失，选择最终配置。

论文的典型设置是在 2k、4k、8k 长度计算影响，12k 长度验证。为避免每层出现太多零散计算形状，实验把每层的不同规则限制为至多两种。它保留头之间的差别，同时让执行仍有规律可循。

下图把这条离线流程连起来。最后留下的是每层、每个头的窗口规则，不是校准样本的 KV，也不是一个新训练出来的路由网络。

![完整模型生成校准回答，反向传播估计连接影响，预算优化产生候选配置，验证后得到可重复使用的窗口规则](/img/posts/paper-moa/offline-search.svg)

因此，校准数据偏向什么能力，搜索就更容易保护什么能力。把配置迁移到不同任务，仍需要检查效果；一阶估计和长度规则都不能保证任意输入下与完整注意力等价。

# 一次推理

## 输入处理

配置选好之后，新会议记录进来，模型仍使用原来的投影权重生成 Q、K、V。区别只是每个头套上自己的因果窗口掩码，在允许的历史位置内完成注意力。

prefill 阶段要处理输入中的全部 query，但每一行只读开头保留区和附近的历史带状区域。没有先计算完整注意力、再把窗口外结果清零的必要；专用稀疏实现可以直接跳过那些计算块。若只是给普通稠密实现加掩码，并不能自动获得相同加速。

处理到记录结尾时，长窗头仍有机会直接读取早先的“青鸟”。短窗头则主要提供附近语句的信息，各个头的输出随后照常合并。模型不是让长窗头替短窗头补算同一个注意力结果，而是在保留原有多头分工的前提下，尽量少破坏重要路径。

## 缓存更新

decode 阶段每次只产生一个新位置。短窗头没必要把完整历史 KV 全存下来：保留开头区域，再留一段固定容量的最近 KV，就足以执行它的读取规则。

[官方缓存实现](https://github.com/thu-nics/MoA/blob/master/MoA/attention/cache_utils.py)使用静态容量和环形更新。开头区域保留不动，新 token 的 KV 写入循环区；循环区填满后，再写入就覆盖其中最旧的条目。不同头可以拥有不同的容量。

下面把时间顺序与物理槽位分开画。缓存槽位不需要随着生成不断拼接扩张，写指针绕回以后，逻辑上最近的一段历史仍然保留着。

![保留开头区域的环形 KV 缓存，新位置覆盖循环区中最旧的条目，容量在本次生成中保持固定](/img/posts/paper-moa/circular-cache.svg)

这与弹性规则并不矛盾：规则处理不同请求长度下的容量分配，静态缓存处理一轮生成中的存储更新。不能把两者理解成“每多生成一个 token，就把窗口扩大一点”，更不能指望扩大窗口后，已经丢弃的历史 KV 自动回来。

# 效率与代价

## 速度来源

从计算量看，解码时完整注意力每个头要读取约 $N$ 个历史位置，MoA 改为读取 $S_h$ 个。密度越低，主要的 KV 读取与注意力计算就越少。但 QKV 投影、FFN 等部分仍然存在，整个模型不会按同样比例变快。

固定密度也不等于把 prefill 的渐近复杂度降成线性。如果跨度中的 $\beta_h N$ 项随输入增长，这个头处理全部 query 的注意力计算仍可有二次项，只是常数更小。MoA 首先是在精度预算内减少实际工作，而不是宣称消除了所有二次开销。

论文的速度提升还包含系统实现。下面取原文 Table 5 的 Vicuna-7B、8k 输入，在单张 A100-80GB 上的解码吞吐。MoA 的平均密度为 50%，表中按消融顺序展开；这些都是作者报告的数据：

| 配置 | Batch | 吞吐量，token/s |
| --- | ---: | ---: |
| HuggingFace FlashAttention2 | 15 | 66.9 |
| 加静态 KV cache | 15 | 219.5 |
| 再减少注意力计算 | 15 | 369.9 |
| 再增大 batch | 25 | 436.7 |
| 再使用专用 kernel，即 MoA | 25 | 535.7 |

同表的 vLLM 是 batch 15、323.0 token/s。因而这组 MoA 数字约为 HuggingFace FlashAttention2 的 8.0 倍、vLLM 的 1.66 倍，而不是“换个窗口，任何推理框架都能快八倍”。

这里比较的是一块 GPU 同时服务多个序列的总吞吐。少存 KV 后可以容纳更大的 batch，这本身就提高了吞吐，不能将倍数直接当作单请求延迟的改善。静态缓存管理也贡献了很大一部分，它不是异构窗口独有的收益。

## 保留的能力

模型效果方面，论文 Table 3 固定 25% 平均密度，逐步扩展搜索空间。8k 输入的检索准确率从统一窗口的 25%，提高到仅层间异构的 31%，再到头间异构的 95%，加入弹性规则后为 98%。

这组消融很贴合 MoA 的动机：只承认不同层有差别还不够，同一层内部的头也不能一刀切。弹性规则则让同一配置能面对多种输入长度，不必每个长度重新搜索。但这个 98% 属于特定模型、密度和检索测试，不代表任意长文任务的准确率。

读论文时，还要区分**输入长度、单头跨度、有效上下文长度**。第一个是送进模型多少 token，第二个是某个头直接读多少，第三个是某项测试中仍能保持指定效果的输入长度。论文把检索准确率超过 90% 的最大输入长度称为有效上下文长度。

部分头保留长距离通路，所以有效上下文可以大于平均缓存长度。这不意味着每个头都能恢复全部被删信息，也不意味着原模型的上下文能力凭空扩大了同样倍数。

## 实现边界

MoA 不生成全局摘要，也不为当前内容动态找回窗口外 KV。若关键连接被校准过程低估，推理时没有额外的候选搜索替它兜底。保留长窗头与保留所有信息，是两件事。

搜索本身也有成本。生成校准回答、计算影响和验证方案都要运行大模型；“免训练”省掉的是权重更新，不是免 GPU，更不是免离线工作。配置复用得越多，这笔一次性成本才越容易摊薄。

工程上，[官方仓库](https://github.com/thu-nics/MoA)还提醒：使用其 kernel 测试 GQA 模型时，需要先转换成 MHA。GQA 原本让多个 query 头共享 KV，逐头不同窗口会涉及共享缓存怎样布局，不能把 MHA 下的节省直接照搬过去。文中结果应放回对应的模型、转换方式与实现条件中理解。

# MoA 与 MiTA

回到记录里的项目代号，两种方法在不同阶段决定“能读什么”。

MoA 提前根据校准数据，为头分配连续的读取范围。请求进来后，不再判断“青鸟”值不值得保留，而是照窗口规则执行。它把复杂的决策放在离线，把在线的计算留得规整，代价是不能根据当前内容临时改变稀疏位置。

MiTA 则在当前输入上，让地标扫描全部 key，准备内容相关的 Top-k 候选和全局摘要。一个很远的位置也可能被选中；没有被选中的信息，还可能通过摘要影响输出。但地标搜索、候选收集和 query 路由都要在前向计算中完成。

**MoA 主要回答预算应该留给哪些头，MiTA 主要回答当前输入中哪些信息值得读取原样。** 前者复用的是离线配置，后者复用的是本次输入的搜索结果。两者都在减少不必要的读取，却没有使用同一套近似；它们的论文实验场景也不同，不能拿各自的加速倍数直接排名。

# 结语

MoA 没有给注意力增加一个更聪明的在线搜索器，而是先弄清楚哪些头不能轻易缩短，再把不同窗口固化成可执行的计划。

沿着它的计算过程看，校准数据决定要保护什么，梯度估计哪些连接可以少读，预算搜索决定空间怎样分配，静态稀疏执行把这份取舍变成实际收益。窗口公式只是最后留下的简洁结果，真正需要理解的是这份配置怎样得来，又省掉了哪些工作。
